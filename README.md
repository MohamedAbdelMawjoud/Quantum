# 🧠 Quantum Support Vector Machine

A QSVM extends the idea of a classical Support Vector Machine by using a quantum computer to map classical data into a high-dimensional **Hilbert space**.

The workflow can be summarized as:

```text
Classical Data
      ↓
Preprocessing
      ↓
Quantum Feature Map
      ↓
Quantum State Encoding
      ↓
Quantum Kernel
      ↓
Kernel Matrix
      ↓
Classical SVM
      ↓
Prediction
```

### Classical SVM

A classical SVM attempts to find an optimal hyperplane that separates different classes.

However, some datasets are not linearly separable in their original feature space.

### Quantum Kernel Approach

QSVM addresses this by mapping the classical data into a quantum feature space.

The quantum kernel measures the similarity between two encoded quantum states:

$$
K(x_i,x_j)=|\langle\phi(x_i)|\phi(x_j)\rangle|^2
$$

where:

* \(x_i\) and \(x_j\) are classical data points.
* \(|\phi(x)\rangle\) is the quantum state generated by the feature map.
* \(K(x_i,x_j)\) is the quantum kernel value.

The resulting kernel matrix is then passed to a **classical SVM**.

# 🧩 Quantum Feature Map

The project uses a **Bloch-sphere / dense-angle encoding** approach.

For a feature vector:

$$
x=[x_0,x_1,\ldots,x_{d-1}]
$$

the encoding uses:

```text
RX(x[0] / 2)
RZ(x[1])

RX(x[2] / 2)
RZ(x[3])

...
```

Each pair of classical features is mapped to one qubit.

Therefore:

$$
n_{qubits}=\lceil d/2\rceil
$$

For example, a 6-dimensional input requires:

```text
ceil(6 / 2) = 3 qubits
```

The corresponding Qiskit circuit is constructed using:

```python
def bloch_feature_map_circuit(x):
    d = len(x)
    n_qubits = int(ceil(d / 2))

    qc = QuantumCircuit(n_qubits)

    for i in range(n_qubits):
        idx0 = 2 * i

        if idx0 < d:
            qc.rx(float(x[idx0]) / 2.0, i)

        idx1 = 2 * i + 1

        if idx1 < d:
            qc.rz(float(x[idx1]), i)

    return qc
```

# ⚛️ Quantum Kernel Calculation

For every pair of data points, the project constructs a quantum circuit containing:

1. The feature map for the first data point.
2. The inverse feature map for the second data point.
3. Measurement of the resulting quantum state.

Conceptually:

```text
|0>
 ↓
Feature Map(x)
 ↓
Feature Map†(y)
 ↓
Measure
```

The probability of measuring the all-zero state:

$$
P(00...0)
$$

is used as the quantum kernel value.

This allows us to construct a kernel matrix:

$$
K_{ij}=K(x_i,x_j)
$$

# 🧪 Classical + Quantum Hybrid Architecture

The final QSVM implementation follows a **hybrid quantum-classical architecture**.

```text
                 ┌─────────────────────┐
                 │   Classical Data     │
                 └──────────┬──────────┘
                            ↓
                 ┌─────────────────────┐
                 │ Data Preprocessing   │
                 └──────────┬──────────┘
                            ↓
                 ┌─────────────────────┐
                 │ Quantum Feature Map │
                 └──────────┬──────────┘
                            ↓
                 ┌─────────────────────┐
                 │ Quantum Kernel      │
                 └──────────┬──────────┘
                            ↓
                 ┌─────────────────────┐
                 │ Kernel Matrix       │
                 └──────────┬──────────┘
                            ↓
                 ┌─────────────────────┐
                 │ Classical SVM       │
                 └──────────┬──────────┘
                            ↓
                 ┌─────────────────────┐
                 │ Classification      │
                 └─────────────────────┘
```

The quantum circuit is responsible for generating the **kernel**, while the optimization and classification are performed by the classical SVM.

This makes the approach a **hybrid Quantum-Classical Machine Learning model**.

# ⚠️ Computational Challenge

One of the most important lessons from this project was the computational cost of quantum kernel methods.

For a training dataset with \(N\) samples, the kernel matrix requires approximately:

$$
O(N^2)
$$

pairwise kernel evaluations.

For example:

```text
100 samples   → 10,000 pair evaluations
500 samples   → 250,000 pair evaluations
1000 samples  → 1,000,000 pair evaluations
```

When every pair requires a quantum circuit simulation, execution time can increase significantly.

This becomes even more noticeable when using classical simulation instead of an actual quantum processor.

Therefore, **dataset size and quantum circuit execution cost are important practical considerations for QSVMs.**
